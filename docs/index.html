Email on your own domain, on Cloudflare.

Receive mail for you@yourdomain.com, read it in a small web inbox, and reply from the same address. One Worker, no mail server.

Try the demo inboxView on GitHub

Four Cloudflare pieces, one Worker.

Everything runs in your own Cloudflare account. Your mail is stored in your D1 database and R2 bucket, not on someone else's server.

01 receive

Email Routing

Mail to your domain goes to the Worker's email() handler.

02 store

D1 and R2

Rows in D1; bodies, the original .eml, and attachments in R2.

03 read

Web inbox

Plain HTML, CSS, and JS served by the same Worker.

04 send

Email Service

Replies leave as your address, signed with DKIM.

Small, but complete.

What you need from a personal or small-team inbox, and nothing that needs a server to babysit.

  • Several addresses on one domain, each with a display name; switch any of them off.
  • Safe reading: sandboxed HTML, no scripts, remote images hidden until you ask.
  • Reply and forward from the address the mail was sent to; a copy is kept in Sent.
  • Folders and search: inbox, starred, sent, archive, spam, trash.
  • Copies and blocks: forward to another inbox, refuse senders or whole domains.
  • Keyboard and phone: c, /, j, k, e, r; one pane at a time on small screens.

Set up in about ten minutes.

You need a domain whose DNS is on Cloudflare. The full steps are in the README.

# storage and a password
npx wrangler d1 create surel
npx wrangler r2 bucket create surel-mail
npx wrangler secret put SUREL_PASSWORD

# schema and Worker
npm run deploy

# then in the dashboard:
#  Email Routing → Catch-all → Send to a Worker → surel
#  Email Service → Email Sending → Onboard Domain

Receiving is free. Sending to any recipient needs the Workers Paid plan; on the free plan the Worker can send to addresses verified in Email Routing. Email Sending is in beta, with a daily quota that grows over time.
